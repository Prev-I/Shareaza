# previ.8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 2.7.11.3 (`v2.7.11.3-previ.8`), the first announced release: attested, immutable, verifiable, with the deferred minor fixes from the previ.7 reviews.

**Architecture:** Three pull requests into `main`. A (`prev-i/previ8-release`, which also carries the design and this plan) changes only workflows and docs, so it merges first and is rehearsed. B (`prev-i/previ8-fixes`) carries the client, installer, oracle and translation fixes. C (`prev-i/version-2.7.11.3`) carries the version. Repository settings and the release are executed step by step, each outward step after the owner's go.

**Tech Stack:** GitHub Actions (`actions/attest-build-provenance`, `gh` ≥ 2.81), C++/MFC (v143), Inno Setup 6, Windows PowerShell 5.1, g++ for the header-only unit test.

**Spec:** `docs/superpowers/specs/2026-11-10-previ8-design.md`

## Global Constraints

- **Testing.** No Windows build here. Each task's test is a check script in `.superpowers/sdd/2026-11-10-previ8/` (git-ignored), run before the change (must FAIL) and after (must PASS); `ReleaseNotes.h` also gets real g++ unit tests. CI's MSBuild and the oracles are the real gate.
- **Pins.** `actions/attest-build-provenance@4d101475d8b20a2381f78447822ac1eab6504dd8 # v4.2.2`; `softprops/action-gh-release@8a0cd651e5b2365bd640854a3fa5dfc70e4875f3 # v3.0.4`. Every action stays pinned by full commit SHA with a version comment.
- **Minimum `gh`** in user instructions: 2.81.0 (`release verify`); never below 2.67.0 (CVE-2025-25204).
- **Release notes and generated release body:** ASCII, no `%`; the owner's first paragraph plain, about 330 characters.
- **Asset names:** `iShareaza_<version>_<Win32|x64>_Release_<YYYY-MM-DD>.exe` plus `SHA256SUMS.txt`. ISCC never gets `RELEASE_BUILD`.
- **The upgrade window:** five controls in today's order and types; the translations key on them.
- **Upgrade prompt:** at most 400 characters in total, ellipsis included.
- **Version:** 2.7.11.3. `SMART_VERSION` unchanged.
- **Commits** are conventional, English, and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Messages and docs** describe changes by class and function only. The reviewer checks trigger disclosure as a named item on every pull request and on the release notes.
- **Outward steps** (push, tag, repository settings, publishing, opening pull requests) wait for the owner's go. **After a pull request is handed to the owner, push nothing more to it.**

## Review Focus

1. **Release notes with a code block or an HTML comment spanning a blank line.** Nothing from inside it may become the summary. Owned by Task 4 (tests `fenced block across a blank line`, `comment across a blank line`).
2. **Underscores and asterisks that are not emphasis** (`snake_case`, `file_name.exe`, `5 * 3`). They must survive. Owned by Task 4 (test `non-emphasis marks kept`).
3. **A long version string plus a long first paragraph.** The whole prompt stays ≤ 400 characters. Owned by Task 4 (test `prompt total within 400`).
4. **An install with random port, or whose first listen fails and re-randomises.** The firewall check runs on the port actually listening, once per port. Owned by Task 7's check script.
5. **A user's existing list already at 50 G2 caches with a blocked copy of an unbanned cache.** After the merge the cache is listed as a working G2 cache, and the shipped defaults are present. Owned by Task 6's check script.
