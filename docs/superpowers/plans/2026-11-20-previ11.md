# previ.11 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the client's own update download connect regardless of IP lists and security rules, and ship the small fixes deferred from previ.9 and previ.10, as 2.7.11.6.

**Architecture:** A per-connection flag on `CConnection`, set only by `CDownloadTransferHTTPS` for a download with `m_bRequireValidCert`, makes `ConnectTo` skip `Security.IsDenied`. The deferred fixes are local edits in `CSecurity`, `CDatagrams`, `CNetwork`, `CMutexTracked`, the update check's asset choice (moved into a pure header with a g++ test, like `ReleaseNotes.h`) and `docs/DIAGNOSTICS.md`.

**Tech Stack:** C++ (MFC, Visual Studio 2022, toolset v143), g++ unit tests for MFC-free headers, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-19-previ11-design.md`

## Review Focus

1. **The update download resumes after a restart.** `m_bRequireValidCert` is saved with the download, and the flag is set on each `Initiate`, so the exemption still holds. Task 1 sets the flag on every `Initiate`; Task 7 checks it by hand.
2. **Another download from the same CDN while the update runs.** It is still refused, because the flag lives on each transfer object, not on the address. Task 7, step 3.
3. **The deny-by-default policy is on.** The update connects; P2P connections and other downloads are still denied. Task 7, step 4.
4. **`Security.dat` moves between versions.** A file written by previ.11 loads in previ.10, which reads the count and gets every rule; a file written by previ.10 loads in previ.11, where IPv6 single-address rules saved by previ.10 are already lost, nothing more. Task 3, step 5 records it.
5. **An imported rule lands on an address that already holds a rule with another GUID.** One rule remains, the imported one, and the old one is freed. Task 3, step 4.
